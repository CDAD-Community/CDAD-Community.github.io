The CDAD Approach

Governed Context for AI-Assisted Development

Context becomes an explicit, governed part of software development. Making architecture, decisions and constraints explicit protects engineering intent.

The Core Idea

CDAD doesn't try to make AI agents smarter. Instead, it makes the development environment more reliable by establishing governed context that the agent must respect.

The foundation is simple: context is an engineering asset. Just like you version control source code, you should version control and protect the context that guides AI agents.

Instead of:

  • "Hope the agent understands the architecture"
  • "Write detailed prompts each time"
  • "Review and fix the agent's output"

CDAD establishes:

  • Explicit, governed context that persists across sessions
  • Clear rules and boundaries that are reviewable and versioned
  • Protected context that the agent cannot bypass
  • Deterministic validation that catches drift automatically

The Five-Step Flow

How CDAD structures the development process.

1

Specification

Define requirements and expected behavior (SDD)

2

Governed Context

Establish architecture, rules and constraints explicitly

3

Governance

Protect context and establish clear agent boundaries

4

AI Agent

Execute development tasks within governed boundaries

5

Validated Software

Verify output and detect architectural drift

Key Principles

The principles that guide CDAD.

Context is Explicit

Architecture, decisions, rules and constraints are written down and versioned. Nothing exists only in conversation or tribal knowledge.

Context is Protected

Critical context cannot be freely modified by an agent. Changes follow a governed process with human review.

Context is Traceable

All changes are reviewable through Git history. You can see what changed, who changed it, why and when.

Governance is Deterministic

Where possible, governance is enforced through code (CI gates, hooks, validation scripts) not just instructions.

Boundaries are Clear

The agent knows what it can modify, what requires review, and what cannot be changed. No ambiguity.

Drift is Detectable

Changes that deviate from the architecture are caught automatically through validation and review processes.

Not About Making AI Smarter

CDAD doesn't attempt to improve the AI model itself. It improves the environment the agent operates in.

Traditional Approach
Better prompts → Smarter answers
    (Still context-dependent)
CDAD Approach
Governed Context + Clear Boundaries
→ Reliable Development Environment
    (Context is protected)
