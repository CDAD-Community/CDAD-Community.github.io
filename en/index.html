The Problem: Architectural Drift

AI coding agents are powerful, but software development requires more than generating code.

🧠

Context Loss

AI agents can lose important architectural, business and technical context during development sessions.

⚠️

Uncontrolled Changes

Without explicit boundaries, an agent may modify parts of the system it should not touch.

🔄

Inconsistent Decisions

Different prompts and sessions can produce different implementations of the same architectural intent.

🛡️

Governance Gap

AI-assisted development needs explicit rules, responsibilities and controlled context.

When Should You Use CDAD?

CDAD is particularly useful when AI agents participate actively in implementation and architectural consistency matters.

🏢

Existing Systems

When agents must work safely inside an existing architecture with established conventions and dependencies.

🤖

AI Coding Agents

When Claude Code, Kiro, Cursor, Copilot or other AI development agents become part of the engineering workflow.

🧭

Architecture Governance

When architectural decisions must remain explicit, reviewable and protected from unintended agent changes.

🔁

Long-Lived Projects

When multiple sessions, agents and developers need to preserve the same project knowledge and engineering intent.

CDAD and SDD

CDAD complements Spec-Driven Development (SDD) by adding a governance model for context, architecture and rules consumed by AI coding agents.

SDD defines what to build

Specification-Driven Development makes requirements, expected behavior and implementation intent explicit and reviewable.

CDAD governs how agents work

CDAD treats project context, architectural decisions, constraints and agent rules as governed engineering assets that can be protected.

How they complement each other

SDD can define what should be built; CDAD governs the context and boundaries that guide an AI agent while it builds it.

Not a replacement

CDAD does not replace SDD. The two approaches work together in modern AI-assisted software development.

Designed for AI Coding Agents

CDAD is an approach, not a replacement for your preferred development agent.

Frequently Asked Questions

Common questions about CDAD, its concepts and how to get started.

What is CDAD?

CDAD (Context-Driven AI Development) is an open-source methodology for governed AI-assisted software development that combines specifications, context engineering, governance and protection patterns.

Is CDAD a replacement for SDD?

No. CDAD complements SDD. SDD focuses on explicit specifications; CDAD focuses on governing the context, architecture, rules and boundaries used by AI-assisted development.

Is CDAD an AI coding agent?

No. CDAD is a methodology and governance approach that can be applied around different AI coding agents and development tools.

What is the Context Protection Pattern?

CPP is a CDAD pattern for protecting governed project context and making changes to critical engineering knowledge deliberate and reviewable.

What is architectural drift?

Individually reasonable AI-generated changes that gradually move a system away from its intended design. CDAD helps prevent this.

Where do I start?

Start with the open-source CDAD Bootstrap project. Clone it, understand the governed context structure, then adapt rules and protection mechanisms to your project.
