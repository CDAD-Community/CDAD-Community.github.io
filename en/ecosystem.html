CDAD & the Ecosystem

Complementary to SDD, Context Engineering & AI Development

CDAD is not a replacement for existing methodologies. It's a complementary governance approach that works alongside SDD, Context Engineering and modern AI development practices.

CDAD Position

CDAD vs SDD

Spec-Driven Development and CDAD answer different questions.

SDD

Question: What should be built? What behavior is required?
Focus: Explicit specifications and expected outcomes

CDAD

Question: How should the context govern AI development? What boundaries protect architecture?
Focus: Governed context and agent governance

Together

SDD defines WHAT to build. CDAD governs HOW an AI agent should operate while building it. They complement each other.

Not Replacement

CDAD does not replace SDD. You can use both methodologies in the same project effectively.

CDAD vs Context Engineering

Context Engineering is a broader discipline. CDAD applies it specifically to AI-assisted development.

Context Engineering

Broad discipline focusing on designing and supplying useful context to AI systems in general.

CDAD

Applies context engineering specifically to software development with AI agents, adding governance, architecture and protection patterns.

Relationship

CDAD is Context Engineering + Software Architecture + Governance + Protection Patterns applied to AI-assisted development.

Integration

CDAD uses context engineering principles but adds software development-specific governance mechanisms.

CDAD vs RAG

RAG and CDAD solve different problems at different layers.

RAG (Retrieval-Augmented Generation)

A retrieval technique for supplying relevant information to an AI system. Solves: "How do I give the AI better information?"

CDAD

A development methodology for governing AI-assisted software development. Solves: "How do I keep the architecture consistent while AI builds?"

Can Complement

CDAD can use RAG to retrieve context. But CDAD is not RAG. CDAD is governance; RAG is retrieval.

Different Concerns

RAG: Information retrieval. CDAD: Context governance, architectural intent, rules enforcement.

CDAD vs Prompt Engineering

Prompt engineering and CDAD operate at different levels of abstraction.

Prompt Engineering

Asks: "How should I phrase instructions so the AI understands them better?"
Focus: Instruction quality and phrasing

CDAD

Asks: "How should the development environment itself be structured so the AI behaves correctly?"
Focus: Context governance and architectural protection

Scope Difference

Prompt engineering: One interaction. CDAD: Entire development process across multiple sessions.

Relationship

CDAD is not "better prompt engineering". It's a different approach addressing structural governance vs. instruction phrasing.
