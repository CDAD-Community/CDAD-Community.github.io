CDAD & el Ecosistema

Complementario a SDD, Context Engineering & Desarrollo de IA

CDAD no es un reemplazo para metodologías existentes. Es un enfoque de gobernanza complementario que funciona junto a SDD, Context Engineering y prácticas modernas de desarrollo de IA.

Posición de CDAD

CDAD opera en la intersección de múltiples disciplinas, proporcionando gobernanza para desarrollo asistido por IA.

CDAD vs SDD

Spec-Driven Development y CDAD responden preguntas diferentes.

SDD

Pregunta: ¿Qué debe construirse? ¿Qué comportamiento se requiere?
Enfoque: Especificaciones explícitas y resultados esperados

CDAD

Pregunta: ¿Cómo debe el contexto gobernar el desarrollo de IA? ¿Qué límites protegen la arquitectura?
Enfoque: Contexto gobernado y gobernanza de agentes

Juntos

SDD define QUÉ construir. CDAD gobierna CÓMO un agente de IA debe operar mientras lo construye. Se complementan.

No es Reemplazo

CDAD no reemplaza SDD. Puedes usar ambas metodologías en el mismo proyecto de manera efectiva.

CDAD vs Context Engineering

Context Engineering es una disciplina más amplia. CDAD la aplica específicamente a desarrollo asistido por IA.

Context Engineering

Disciplina amplia enfocada en diseñar y suministrar contexto útil a sistemas de IA en general.

CDAD

Aplica context engineering específicamente a desarrollo de software con agentes de IA, agregando gobernanza, arquitectura y patrones de protección.

Relación

CDAD es Context Engineering + Arquitectura de Software + Gobernanza + Patrones de Protección aplicado a desarrollo asistido por IA.

Integración

CDAD usa principios de context engineering pero agrega mecanismos de gobernanza específicos del desarrollo de software.

CDAD vs RAG

RAG y CDAD resuelven problemas diferentes en capas diferentes.

RAG (Retrieval-Augmented Generation)

Una técnica de recuperación para suministrar información relevante a un sistema de IA. Resuelve: "¿Cómo doy mejor información a la IA?"

CDAD

Una metodología de desarrollo para gobernar desarrollo asistido por IA. Resuelve: "¿Cómo mantengo la arquitectura consistente mientras la IA construye?"

Pueden Complementarse

CDAD puede usar RAG para recuperar contexto. Pero CDAD no es RAG. CDAD es gobernanza; RAG es recuperación.

Preocupaciones Diferentes

RAG: Recuperación de información. CDAD: Gobernanza de contexto, intención arquitectónica, aplicación de reglas.

CDAD vs Ingeniería de Indicaciones

La ingeniería de indicaciones y CDAD operan en diferentes niveles de abstracción.

Ingeniería de Indicaciones

Pregunta: "¿Cómo debo formular instrucciones para que la IA las entienda mejor?"
Enfoque: Calidad y formulación de instrucciones

CDAD

Pregunta: "¿Cómo debe estructurarse el entorno de desarrollo para que la IA se comporte correctamente?"
Enfoque: Gobernanza de contexto y protección arquitectónica

Diferencia de Alcance

Ingeniería de indicaciones: Una interacción. CDAD: Proceso completo de desarrollo en múltiples sesiones.

Relación

CDAD no es "mejor ingeniería de indicaciones". Es un enfoque diferente abordando gobernanza estructural vs. formulación de instrucciones.
