CDAD

Context-Driven AI Development

A governed approach to building software with AI coding agents — combining context, specifications, rules and protection patterns to produce more reliable software.

Get Started

The Problem

AI coding agents are powerful, but software development requires more than generating code.

🧠

Context Loss

Agents can lose important architectural, business and technical context during development.

⚠️

Uncontrolled Changes

Without explicit boundaries, an agent may modify parts of the system it should not touch.

🔄

Inconsistent Decisions

Different prompts and sessions can produce different implementations of the same architectural intent.

🛡️

Governance

AI-assisted development needs explicit rules, responsibilities and controlled context.

The CDAD Approach

Context becomes an explicit, governed part of software development.

1

Specification

Define what the system must do.

2

Context

Provide relevant project knowledge.

3

Governance

Define rules and boundaries.

4

AI Agent

Execute development tasks.

5

Software

Produce validated changes.

CDAD and the AI Development Ecosystem

CDAD complements modern approaches to AI-assisted software engineering, including SDD, Spec-Driven Development and Context Engineering.

Spec-Driven Development

SDD defines software behavior and requirements through explicit specifications before and during AI-assisted implementation.

Context Engineering

CDAD treats project context as an explicit engineering artifact that can be structured, governed and protected.

AI Coding Agents

CDAD provides a governance layer for AI coding agents such as Claude Code, Kiro, Cursor and other agentic development tools.

AI-Assisted Development

Combine human architectural decisions with AI-assisted implementation while preserving project intent and engineering constraints.

Context Protection Pattern

CDAD introduces explicit protection around the context that governs the agent.
