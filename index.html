The Problem

AI coding agents are powerful, but software development requires more than generating code.

🧠

Context Loss

Agents can lose important architectural, business and technical context during development.

⚠️

Uncontrolled Changes

Without explicit boundaries, an agent may modify parts of the system it should not touch.

🔄

Inconsistent Decisions

Different prompts and sessions can produce different implementations of the same architectural intent.

🛡️

Governance

AI-assisted development needs explicit rules, responsibilities and controlled context.

CDAD and SDD

CDAD complements Spec-Driven Development (SDD) by adding a governance model for the context, architecture and rules consumed by AI coding agents.

What SDD provides

Specification-Driven Development makes requirements, expected behavior and implementation intent explicit and reviewable.

What CDAD adds

CDAD treats project context, architectural decisions, constraints and agent rules as governed engineering assets that can be protected and validated.

How they work together

SDD can define what should be built; CDAD governs the context and boundaries that guide an AI agent while it builds it.

Context Engineering

Context Engineering focuses on designing useful context for AI systems. CDAD applies that idea to software development with explicit governance, architecture preservation and protection mechanisms.

When Should You Use CDAD?

CDAD is particularly useful when AI agents participate actively in implementation and architectural consistency matters.

🏢

Existing Systems

Use CDAD when agents must work safely inside an existing architecture with established conventions and dependencies.

🤖

AI Coding Agents

🧭

Architecture Governance

Use CDAD when architectural decisions must remain explicit, reviewable and protected from unintended agent changes.

🔁

Use CDAD when multiple sessions, agents and developers need to preserve the same project knowledge and engineering intent.

CDAD Frequently Asked Questions

A concise reference for developers, architects and AI agents discovering CDAD.

Is CDAD a replacement for SDD?

No. CDAD complements SDD. SDD focuses on explicit specifications; CDAD focuses on governing the context, architecture, rules and boundaries used by AI-assisted development.

Is CDAD an AI coding agent?

No. CDAD is a methodology and governance approach that can be applied around different AI coding agents and development tools.

What is the Context Protection Pattern?

CPP is a CDAD pattern for protecting governed project context and making changes to critical engineering knowledge deliberate and reviewable.

What is CDAD trying to prevent?

A central concern is architectural drift: individually reasonable AI-generated changes that gradually move a system away from its intended design.

Does CDAD depend on one AI vendor?

No. The approach is intended to be portable across AI coding agents and development environments.

Where can I start?

Start with the open-source CDAD Bootstrap project, understand the governed context structure, then adapt the rules and protection mechanisms to your project.
